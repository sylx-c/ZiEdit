# 全项目优化：可靠性第一阶段

日期：2026-11-01。实施与验收记录以 `docs/tmp/phase1/` 实际报告为准。

## 本阶段

- 跨平台恢复：Windows DPAPI；Unix 0600 明文快照、默认目录 0700，自选已有目录权限保持。原子写失败保留旧副本，异常条目展示原因且恢复其它条目不清除它。
- DocumentSessionStore 集中文档缓冲、版本、元信息、恢复内容及 Markdown Worker 生命周期。关闭使旧回调失效；保存仅确认提交版本；另存为写盘前阻止覆盖其它脏标签，来源/目标中途编辑均保留。
- 工程验证与构建溯源：源码摘要涵盖 Git 管理及未忽略文件，记录完整提交/dirty、工具链、检查日志与包哈希；源码变更使旧报告失效；打包失败恢复旧包，成功后淘汰旧包。
- 文档统一工程版本 1.0.0、Node 24、实际 PDF 能力及资产授权机制；CI 保持三平台检查和打包，缺包失败。

## 验证入口

`node scripts/verify-project.mjs` → `verification.json`，包含前端、Rust、许可与溯源检查。
`node scripts/build-verified.mjs` → `build-manifest.json`，验证报告与构建前后源码一致才接受安装包。
原生隔离构建与门禁日志位于 `native-build.log`、`native/`；原生验证不由工程检查替代。

已出现并保留的诊断：首次全量测试几何等待超时，单跑通过；第二次全量表格窗口断言失败，单文件 55 项通过。最终结果以限制并发后的完整报告为准。许可生成器原有检查发现清单过期，已按锁文件重生成并保留文件换行。
