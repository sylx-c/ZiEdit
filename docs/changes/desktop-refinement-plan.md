## 1. 修订结论

用户反馈上一版“太普通”，同时明确喜欢当前工作台格局。因此本版不再通过删减菜单、合并区域或扩大空白制造变化，而是采用“信息架构不变，视觉语言重做”的策略。

保留：六个菜单、完整分组工具栏、双层文件/大纲侧栏、目录树、连续卡片标签、标尺、右侧缩略图、分段状态栏，以及当前编辑与预览习惯。

精修：色彩气质、双色图标、分组线、选中标记、目录层级、阅读排版、状态反馈、主题预览和键盘细节。

本版设计命名为“蓝墨 / Precision Paper”：不是换成另一种工具，而是让熟悉的 ZiEdit 更精确、更有自己的质感。

## 2. 新视觉语言

### 2.1 纸面与墨色

- 浅色正文采用略暖的纸白，避免普通纯白工作台的苍白感；外壳仍为冷灰，形成轻微微差。
- 正文使用深墨蓝黑，而不是绝对黑；品牌钴蓝用于当前文件、标签短标、章节标记、焦点和关键状态。
- 深色版沿用相同比例：石墨纸面、浅墨文字、柔和蓝光标，不用纯黑边框切割所有区域。
- 不引入大面积渐变、装饰插画、玻璃拟态或持续动画。辨识度来自一致的细节，不来自视觉特效。

### 2.2 保留工具栏的功能色彩

与上一版不同，不再将普通工具全部中性化。保留文件蓝、编辑紫、查找青、视图琥珀四组功能色，但降低彩度并统一双色结构：

- 图标保持16px网格与原有工具语义，以细线、浅色纸面和少量实心细节形成统一风格。
- 细分组线划分文件、剪贴板、查找与格式，不用额外卡片包裹每组。
- hover使用同组浅色底，active/toggle增加内框和小标记；禁用态降低不透明度但不伪装成可点击。
- 品牌蓝只负责选中与焦点，差异、错误、警告和语法仍保留独立语义色。

### 2.3 同一个“蓝色插入标记”母题

将品牌图标的蓝色光标转译为工作台细节：

- 活动标签顶部使用短蓝色标记，而不是整条厚重下划线。
- 当前文件行使用2px定位标记与浅蓝底，目录树保留细缩进线。
- Markdown二级标题使用短蓝色章节标记；引用使用蓝色左边线与低饱和底色。
- 当前模式在状态栏保留浅蓝格；未保存继续使用小方点。

这些细节重复同一形状语言，但不过度复制到每一行文字。

## 3. 保留格局的实测规格

现状证据来自现有[样式](../../src/styles.css)、[工作台装配](../../src/shell/app.ts)、[控件与命令](../../src/shell/chrome.ts)和前次浏览器走查。现版大致为标题32px、菜单28px、工具栏32px、标签28px、标尺19px、状态28px、侧栏232px。

本版只做小幅光学校正，不重排核心结构：

| 区域 | 蓝墨 V2 | 设计目的 |
| --- | --- | --- |
| 标题/菜单 | 32px / 28px，位置不变 | 保持窗控、六菜单及拖拽习惯 |
| 工具栏 | 34px，26px图标按钮；紧凑24px | 比原来多2px呼吸，不改变分组与命令 |
| 侧栏 | 236px；文件视图29px，页签区27px，筛选26px | 保留双层结构，改善17px小页签的可读性 |
| 目录树 | 24px行；紧凑22px | 保留root/docs/src/data层级和展开行为 |
| 文件标签 | 30px连续卡片，短蓝标 | 保持卡片衔接、关闭与未保存反馈 |
| 标尺/右轨 | 20px / 94px | 保留辅助区，缩略图增加清晰视口框 |
| 状态栏 | 28px，20px平面分段格 | 去掉Win32凹凸明暗边，但保留用户熟悉的单元格结构 |
| Markdown | 14px / 1.95，正文列总宽820px（含留白） | 14px保持桌面效率；标题27px、二级18px形成明确层级 |
| 源码 | 12.5px等宽，约1.95行高 | 沿用JetBrains Mono，不改变正式版字号偏好 |
| 圆角 | 控件4–5px，弹层10px | 精密而非过分圆润；图标保持16px |

Demo采用hex方便视觉评审；生产继续使用现有OKLCH主题ID与角色映射，不新增重复主题。UI字体沿用系统字体；代码字体沿用捆绑资源，无CDN、在线字体或统计依赖。

## 4. 关键区域整改

### 4.1 顶部与工具栏：不删功能，只减噪声

- 保留左段恒定操作、中段上下文操作、右段命令/主题的既有结构；相关用户决策见[app.ts:5126](../../src/shell/app.ts#L5126)。
- 六菜单原样保留，弹出项统一图标、快捷键列与hover/focus反馈。
- 工具栏在960px桌面最小窗保持完整单行；更窄窗口采用有序溢出，不能挤压或换行引起编辑区跳动。
- Demo在低于桌面最小窗时隐藏部分格式按钮，仅用于响应式探查；生产实施必须提供溢出菜单与命令入口，不能静默丢功能。
- 不为视觉改变编辑锁、Markdown模式或保存行为。

### 4.2 侧栏：从密集列表变成清晰导航

- 保留“文件视图 + 收藏/最近/切换”以及“文件/大纲”两层，不再合并成通用侧栏。
- 文件筛选采用明确的边框、图标、快捷键提示和focus-within反馈。
- 目录展开、过滤、已加载行边界和恢复规则不变；不得为Demo效果递归扫描文件系统。
- 文件类型色、当前行蓝标、未保存点统一；长文件名仍需tooltip和路径辨识。

### 4.3 Markdown：有阅读气质，但仍是生产力工具

- 标题不再使用展示页式巨字；27/18px标题与14px正文构成更紧凑、真实的编辑文档。
- 默认阅读列820px（含54px内边距），比旧版1200px上限更适合中文长文；正式宽度需用户评审。
- 引用、列表、代码块和表格有层次但不过度卡片化。代码块使用轻灰底、细边和小型语言标题。
- 源码、预览、分屏、即时渲染四模式及草稿默认行为依[PRD](../PRD.md)保留。Demo只模拟源码与即时阅读切换。
- 数学、图表、代码高亮、表格编辑、块身份、滚动锚与增量解析不得因视觉改版重写。

### 4.4 标签、标尺与缩略图：保留喜欢的工具感

- 活动标签保持连续卡片形态，顶部短蓝标替代厚重装饰。
- 标尺保留列刻度，主/次刻度与文字分别控制对比度，与代码行号保持列对齐。
- 缩略图保留常驻右轨，视口框用品牌蓝细线和低透明底表示；不默认自动隐藏。
- 标尺、缩略图、字体等已有设置继续生效。Demo提供的开关不替代生产偏好。

### 4.5 状态栏与弹层：精修而不是消除结构

- 状态栏仍按模式、光标、编码、语言、字数、保存与权限分段；只将Win32凹凸边换成统一的1px平面边。
- 当前模式使用浅蓝底，保存与错误用语义色；交互格保留按钮语义、焦点、hover和下拉提示。
- 窄窗按优先级收敛非关键元信息，未保存、只读、保存失败、编码风险不能被静默隐藏。
- 主题卡展示真实工作台缩略结构，radio组支持方向键；命令面板有dialog/combobox/listbox关联、过滤、选中与焦点返回。

## 5. Demo 能体验什么

新版为独立HTML/CSS/JavaScript原型，生产src/未修改。包含：

- 六菜单与完整工具栏；Markdown格式插入、标题切换、源码/阅读切换、编辑/只读锁。
- 三层目录树、文件筛选、文件/大纲、关闭和重新打开示例标签。
- TypeScript编辑与示意语法高亮；CSV只读单元格定位。
- 四主题、两档密度、标尺/缩略图开关、点击缩略图定位。
- 查找首项、命令过滤与方向键执行、下载当前文本。

边界：所有编辑只修改当前页面内存，刷新恢复示例。下载不回写真实文件；系统窗控仅为装饰；Markdown为有限安全转义渲染器；TypeScript高亮为轻量示意；CSV无RFC4180解析；文件系统、IME、虚拟化、PDF/Office/对比等不属于原型能力。

## 6. 分阶段实施

### P0 · 原布局视觉精修

目标：不动信息架构，先获得新版质感。

1. 在现有主题token中映射纸白、墨色、钴蓝、细线和功能色；保持四主题名称与旧配置。
2. 按蓝墨规范调整图标双色、工具栏分组线、hover/active/disabled，不改ActionRegistry与工具组顺序。
3. 调整侧栏页签、目录行、活动文件标记；保留文件树行为与展开状态。
4. 标签增加短蓝标；状态栏去凹凸但保留分段；统一菜单、主题卡、命令面板的焦点与语义。
5. 截图对比现有与新版，逐项核对菜单、上下文工具、状态信息和快捷键。

涉及：styles.css、shell/chrome.ts、shell/sidebar.ts、shell/panels.ts、shell/app.ts、common/i18n.ts。

通过条件：六菜单与全部动作入口不减少；960px工具栏无裁切；四主题的默认/hover/active/disabled/focus可读；状态栏未保存与锁状态准确；键盘可完成主题和命令操作。

### P1 · 排版与密度精修

目标：在认可P0后改善阅读，不重排工作台。

1. 将Markdown标题、正文、引用、代码和表格样式映射到四主题；保留四模式及滚动锚。
2. 提供可选舒适/紧凑密度，不覆盖现有用户偏好；确认字号、侧栏宽度与阅读列的正式默认值。
3. 标签溢出、长路径、长英文菜单、系统缩放和弹层边界回归。
4. 如需窄窗溢出，先建立统一溢出菜单并确保命令面板可访问全部动作。
5. 不合并标题/菜单/工具栏，不取消标尺和缩略图，不新增常驻欢迎页。

涉及：shell/app.ts、shell/chrome.ts、shell/outline.ts、common/state.ts、common/i18n.ts、markdown-view/layout.ts、preview.ts、livepreview.ts、text-view/minimap.ts、styles.css。

### P2 · 全格式与边界状态收口

- CSV/TSV沿用中性表头、选中与定位规格，保留扫描、分隔符和虚拟视口。
- 图片查看保留透明棋盘和图像本色，统一缩放/旋转/守护控件。
- PDF正文页面保持原色白底，主题只影响外壳；不夸大canvas的正文无障碍能力。
- docx/xlsx只读提取、失败与上限提示使用同一状态组件，保留有界提取。
- 双文件对比保留新增/删除/行内差异/不可见字符/A-B语义，不能只用蓝色表达差异。
- 空态、加载、恢复、外部修改、只读、保存失败、超大文件守护卡片统一；风险信息优先于视觉简洁。

涉及：csv-view/table.ts、image-view/view.ts、pdf-view/view.ts、compare-view/view.ts与layout.ts、Office视图模块、shell/app.ts、styles.css。

## 7. 验收与工程约束

| 维度 | 验收内容 |
| --- | --- |
| 视觉 | 4主题×2密度；默认/hover/selected/focus/disabled/error；浅色与深色都检查对比度 |
| 窗口 | 960×600、1280×832、1440×900、1920×1080；100/125/150/200%缩放；长标签与菜单 |
| 平台 | Windows/macOS/Linux窗控、拖拽区、系统菜单、字体与快捷键；不让拖拽区吞按钮 |
| 键盘与读屏 | Tab/方向键/Enter/Esc、弹层焦点返回、角色/名称/状态；Enter不漏进编辑器 |
| Markdown | 四模式、源码/分屏锚、数学/图表/大表/图片、密集文档、IME |
| 数据安全 | 未保存、只读锁、外部修改、保存失败、恢复；视觉改动不导致数据丢失 |
| 大文件 | 保留分块、虚拟化、worker与内存预算，不为Demo效果引入全量DOM |
| 离线 | 断网可用；不增加CDN、联网字体、账号或统计依赖 |

普通文字对比度目标≥4.5:1，大文字与必要控件状态≥3:1；装饰分隔线与禁用态另行判断。颜色不是唯一状态载体。

性能依[PRD](../PRD.md)既有原生门槛：Markdown滚动P95≤32ms、输入到首个可见响应P95≤50ms；密集约2MB语料键入P95≤40ms，无≥100ms长任务；固定阅读锚位移≤4CSS px。小Demo流畅不代表原生达标。

生产实施后运行`npm run build`、`npm test`并补充键盘/溢出/语义回归；实际修改后端再执行Rust测试、clippy和fmt。桌面构建遵循AGENTS，使用Tauri命令；性能门禁按既有prepare-gate-build/run-all流程。

本轮 P0 已修改实际前端样式与弹层语义，独立 Demo 继续保留。真实构建的浏览器走查记录见[新版说明](../design/desktop-refinement-v2/README.md)；操作系统缩放、屏幕阅读器、Tauri 原生窗控与真实文件性能仍需在桌面实施验收中检查。
