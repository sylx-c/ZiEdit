## 这是什么

ZiEdit：跨平台（Windows / macOS / Linux）桌面文件查看与编辑工具，离线优先——全程本地运行，唯一可选联网能力是用户自行配置的 S3 兼容图床。技术栈 Tauri 2 + Rust + TypeScript + CodeMirror 6。

## 给谁用

（推断，待确认）需要在本地频繁查看/编辑大文本与代码、写作 Markdown、快速查看 CSV / 图片 / Office 文档的个人开发者与写作者；重视离线与隐私，不想为查看文件装一整套办公套件。

## 核心三件事

### 1. 大文件文本/代码查看与编辑

- 分块读取（64KB 块 + LRU 缓存）与虚拟滚动：查看态不受文件大小限制；编辑态上限 10MB，超出自动转查看态
- 编码四级探测（BOM → 文件内声明 → 启发式 → 手动覆盖）：GBK / GB18030 / UTF-8/16/32 / Shift_JIS 及 encoding_rs 全部标签；编码转换另存、规范化另存
- 查找替换、批量替换、多文件查找（后台扫描 + glob）、跳转行、书签
- 矩形/列选区与列编辑、粘贴矩阵、IME 合成保护
- 文本正文单击定位、拖选任意字符；行号单击选择整条逻辑行，Shift+行号扩展行范围。自动换行及列模式下同一行拖选仍保留字符选区，当前行高亮不得遮住选区。列键盘扩展保留固定起点，允许反向缩回。
- 自动保存（sidecar/file 双策略）、崩溃恢复快照、日志尾板（2000 行轮询）

### 2. Markdown 写作与预览

- 保留源码、渲染预览、分屏渲染、即时渲染四种模式，沿用默认打开方式和现有大小上限。编辑缓冲保存正文、撤销栈与未保存内容，文档会话统一维护增量解析、块身份及派生元数据。
- 独立预览与分屏右栏共用阅读组件，保留完整正文 DOM、跨段选择复制和全文查找；普通编辑只替换受影响块，特殊语法不触发整篇降级。活动正文不受离屏块缓存数量限制。
- 渲染面右轨按当前排版绘制地图；地图、视口框与滑块读取同版本的布局。分屏最右侧固定控制右栏，两侧按源码锚逐帧双向同步；地图导航保留光标与横向位置。即时渲染由 CM6 管理高度和滚动锚。
- MathJax 数学、Mermaid 图表（securityLevel: strict）、worker 化代码高亮、GFM 表格编辑（虚拟视口）、大纲导航、格式化命令、写作模式
- 可选 S3 图床：SigV4 上传、去重、重命名模板、失败回退；凭据仅会话内存，不随配置落盘

### 3. 多格式查看与文件对比

- 图片查看（缩放/适应/100%/拖拽平移/90° 旋转/超大图守护）、CSV/TSV 表格（Rust 侧 RFC 4180 扫描、分隔符切换）
- docx / xlsx 只读提取、PDF 整页渲染查看（pdf.js legacy 构建：连续滚动、缩放（适应窗/100%/±/Ctrl+滚轮）、页码跳转、90° 旋转、按需测量与渲染、canvas 内存预算、>100MiB 守护卡片；纯画布不支持正文选择/复制/全文搜索/屏幕阅读，无障碍走页码跳转与键盘滚动；wasm 解码器不随包分发，JPEG2000/JBIG2/CCITT 走 JS 回退）；解析失败/加密时回退文本提取通道（旧提取器不支持加密与压缩文本流，文本可能为空）并提供系统查看器出口
- 双文件对比：并排/统一/A-B 三视图 + 行内标注；差异分类（同形字符/Unicode 规范化/不可见字符/空白/内容），500 万行上限

### 工作台能力

草稿（默认纯文本；状态栏语言下拉兼作格式切换器——选定语言即切换高亮与另存扩展名，Markdown 草稿可进源码/分屏/即时渲染三形态）、本标签编辑锁（工具栏「编辑|只读」段，会话级）与全局只读锁定（编辑菜单，作用所有标签）、文件树（多选、收藏、最近、过滤）、命令面板、主题、字体导入、界面缩放、i18n（zh-CN/en-US）、系统文件图标、回收站删除、校验和面板、会话持久化与命名会话、托盘与关闭行为（ask/exit/tray）。

托盘菜单在启动设置加载后和运行时切换语言时，均跟随最终界面语言；未显式保存语言时沿用系统/缓存探测结果。

命令面板的 Enter 只执行所选命令；即使命令同步聚焦编辑器，确认键也不得写入正文。

外部打开唤起（2026-11-04 整改）：通过系统「打开方式」、文件关联或命令行把文件交给已运行实例时，既有主窗先恢复可见、取消最小化并聚焦，再打开目标文件；无文件参数的再次启动同样唤起已有窗口。窗口操作失败不丢弃文件转发。

目录树展开契约（2026-11-04 整改）：打开文件自动跟随到新目录时根目录默认收起，仅显示根行；同目录打开、切换标签、目录刷新与自动会话恢复保留手动展开/收起状态，不自动展开定位。显式「打开文件夹」「返回上级」展开首层；显式定位（如新建后定位、搜索结果跳转）可展开已收起的根。过滤仍只作用于已加载行，不因默认收起引入递归扫描。

## 怎么算成功

- 已有验收体系（事实）：`tests/` 按验收编号组织——ac-001 外壳与会话、ac-002 编辑与查找、ac-005 列粘贴、ac-006 大纲书签、ac-007 Markdown/IR（最大组）、ac-008 对比、ac-009 图床等，测试数量以当次运行报告为准。CI：tsc 与 vitest 在 Ubuntu、Windows、macOS；cargo test、clippy -D warnings、fmt --check 与 tauri build 在三平台。原生性能门禁在 Windows 本机，不阻断合并。
- 用户定义的量化成功指标：**待补**
- Markdown 原生验收目标（2026-10-31）：当前源码经 Tauri CLI 构建，在固定 GPU/刷新率环境从打开开始采样，覆盖 100KB、400KB、1MB、各模式上限，以及普通正文、超大单块和混合内容。滚动帧间隔 P95 ≤32ms，输入到首个可见响应 P95 ≤50ms，交互及停手阶段无 ≥100ms 主线程长任务，1MB 普通正文首屏可读 ≤500ms。最后输入起至少观察 1.5 秒，固定阅读锚位移 ≤4 CSS px；分屏正常布局最终位置在两帧内同步。是否达标以原生报告为准，实施记录见 `docs/changes/markdown-unification.md`。密集语料分档（2026-11-04 用户决策）：约 2MB 密集 Markdown 键入 P95 ≤40ms、无 ≥100ms 主线程长任务且键序正确，16ms 保留为长期目标；输入到首个可见响应 P95 ≤50ms 的要求不变，两类计时口径分别记录。

## 边界与非目标

- 不做版式引擎级 PDF；OOXML 为有界离线读取（docx 正文 32MB、xlsx 索引 256MB、包体 100MiB 等上限）
- 不内置任何云端同步/账号；S3 图床为唯一联网点，端点由用户配置
- 查看态文件在被外部修改时可检测并刷新（EXTERNAL_CHANGED 契约）
