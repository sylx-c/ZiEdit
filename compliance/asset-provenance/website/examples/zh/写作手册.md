# 给想法一个清楚的落点

把零散记录整理成可以继续工作的文档。这份示例为本次 ZiEdit 官网截图新写，内容与人物均为虚构。

## 从一份简单的记录开始

**先写清楚，再慢慢完善。** 用标题区分主题，用短段落说明原因，给下一次打开文件的自己留一点上下文。

- 文本适合随手记录，不需要提前设计结构。
- 代码保留原来的缩进，让阅读顺着逻辑进行。
- Markdown 把说明、清单与代码放进同一份文件。

## 把下一步写得具体

| 事项 | 完成条件 | 状态 |
| --- | --- | --- |
| 整理笔记 | 每条记录都有明确主题 | 已完成 |
| 检查代码 | 输入与输出可以逐项核对 | 进行中 |
| 补充说明 | 示例能在本地直接阅读 | 待处理 |

> 不必一次写得面面俱到。先保留准确的信息，再逐步减少读者需要猜测的地方。
