# Exact-version upstream license evidence

Run `node scripts/collect-upstream-license-evidence.mjs` to collect/resume and `node scripts/collect-upstream-license-evidence.mjs --check` to verify every referenced document offline. No package installation or scripts are executed.

The [manifest](manifest.json) joins by ecosystem/name/version. Document paths are relative to this directory. Every document records its original upstream path, source URL, bytes and SHA-256. Archive-origin documents additionally record the verified archive URL, SHA-256 and npm lock integrity or Cargo.lock checksum. Original upstream bytes are unmodified. Registry metadata, source-tree responses and archive VCS metadata preserve exact-version linkage. Cached HTTP responses are retained under provenance/http for repeatable collection.

UPSTREAM_TEXT_COLLECTED means license evidence exists, not legal clearance of embedded components or a proof of target binary correspondence. Some npm binary packages lack gitHead: their official registry SLSA statement subject SHA-512 is checked against the verified archive, then its immutable gitCommit selects upstream text. Statement signatures and transparency logs are retained but not independently cryptographically verified here.

Original license files from monorepo ancestors explicitly record inheritance. r-efi AUTHORS is manually reviewed as a full MIT grant including copyright; its README confirms the MIT alternative. For cesu8/winapi, original source copyright notices expressly link Apache-2.0; for selectors they expressly link MPL-2.0. Their complete original source notice files plus separately identified official fixed-license-version text are retained. These documents carry evidenceRole=full-license-text and manualEvidence explaining the linkage; they are never presented as fabricated upstream package LICENSE files. selectedLicense records the reviewed branch.

Unresolved entries retain review items. Run node scripts/collect-upstream-license-evidence.mjs --refresh-status for an offline current-lock membership refresh without fetching upstream data. dependencyStatus distinguishes CURRENT_LOCKED_DEPENDENCY from HISTORICAL_NOT_IN_CURRENT_LOCKFILES; historical entries and their findings stay preserved but are not unresolved current runtime dependencies. --check recomputes this distinction from current lockfiles without writing. This evidence store excludes downstream modification analysis and an exhaustive embedded-native-library audit. Full source archives are hashed but not retained here. Corresponding-source delivery and notice obligations remain the responsibility of the distribution inventory.
