# Feature Specification: 标签右键重命名

**Feature Branch**: `002-tab-rename`

**Created**: 2026-11-20

**Status**: Draft

**Input**: User description: "目前在 ZiEdit 打开文件，如果想给文件改名，需要关闭文件去桌面改，我需要直接在标签右键就能重命名"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在打开的标签上直接改名 (Priority: P1)

正在编辑或查看一个已打开文件的人，不必先关闭标签、再离开应用去系统文件管理器改名。在该文件的标签上右键，选择重命名，输入新名称并确认后，磁盘上的文件完成改名，标签继续打开同一份内容，并显示新名称。

**Why this priority**: 这是本次唯一被点名的痛点。没有这一步，用户仍必须中断当前工作去桌面改名。

**Independent Test**: 打开一个可改名的本地文件，在其标签上右键选择重命名，确认一个合法的新名称。文件在原目录下以新名称存在，标签不关闭，内容与未保存修改都还在，标签名变为新名称。

**Acceptance Scenarios**:

1. **Given** 一个已打开的本地文件标签，**When** 用户在该标签上右键，**Then** 菜单中出现重命名，且与关闭、复制路径等既有项并存。
2. **Given** 用户选择重命名，**When** 输入框出现，**Then** 预填当前文件名（含扩展名），用户可改名或取消；取消后文件名与标签都不变。
3. **Given** 用户确认了一个与当前名不同、且不含路径分隔符的新名称，**When** 目标位置没有同名项，**Then** 文件在原目录下完成改名，标签保持打开并显示新名称，短暂提示已重命名。
4. **Given** 该标签有未保存修改，**When** 重命名成功，**Then** 未保存内容仍留在该标签中，不要求用户先保存或关闭。
5. **Given** 重命名的是当前正在查看的文件，**When** 改名成功，**Then** 窗口标题、状态栏路径提示与文件树中的该项同步为新名称与新路径。

---

### User Story 2 - 改名失败时工作不丢 (Priority: P2)

改名可能因为同名已存在、名称非法、文件被占用或权限不足而失败。失败时用户能看懂原因，已打开的内容和标签路径保持改名之前的状态。

**Why this priority**: 改名是对用户文件的写操作。失败若留下半改状态，或把未保存内容绑到错误路径，比「不能改名」更严重。

**Independent Test**: 对已打开且有未保存修改的文件，分别尝试改成已存在的名称、含斜杠的名称、以及一个无法完成的目标。每次失败后，原文件仍在，标签路径不变，未保存修改仍在。

**Acceptance Scenarios**:

1. **Given** 目标目录已有同名项，**When** 用户确认该名称，**Then** 提示同名已存在，原文件与标签都不改。
2. **Given** 新名称含 `/` 或 `\`，或为空，或与当前名相同，**When** 用户确认或关闭输入，**Then** 不发起改名，标签与文件保持原样。
3. **Given** 改名因占用、权限或文件已不存在而失败，**When** 操作结束，**Then** 用户看到失败原因，标签仍指向原路径，未保存修改不丢失。

---

### User Story 3 - 不能改名的标签不提供误导入口 (Priority: P3)

草稿、双文件对比和尾随台没有单一可改名的磁盘文件。这些标签的右键菜单不提供重命名，避免用户以为改的是一个不存在的文件。

**Why this priority**: 入口必须和「这个标签对应哪一份文件」一致。错误入口会造成无效操作或改错对象。

**Independent Test**: 分别打开草稿、对比和尾随台标签并右键。菜单中没有重命名。对普通本地文件标签右键，重命名仍在。

**Acceptance Scenarios**:

1. **Given** 草稿、对比或尾随台标签，**When** 用户右键该标签，**Then** 菜单中没有重命名。
2. **Given** 图片、表格、文档预览等已打开的真实本地文件，**When** 用户在其标签上重命名并成功，**Then** 标签继续打开改名后的同一文件，不要求先切换到文本编辑。

---

### Edge Cases

- 新名称只改大小写，且当前文件系统把大小写视为同一名称时，改名仍应成功，标签显示用户确认的写法。
- 只改扩展名时，标签继续打开该文件，并按新扩展名决定之后如何展示；不静默另存一份。
- 同一目录下另有已打开文件，或子目录中有已打开文件，不受本次单文件改名影响。
- 文件在打开期间已被外部移走或删除时，重命名失败并说明文件不在，不新建空文件顶替。
- 标签被标为只读或全局只读时，仍允许重命名磁盘文件名；只读只限制正文编辑，不限制文件名。
- 重命名进行中用户切换或关闭其他标签时，只迁移被改名的那一个标签及其关联状态（脏标记、只读锁、滚动与视图记忆、最近关闭记录中的该路径）。
- 最近打开与收藏中若记录了旧路径，改名成功后这些记录指向新路径，避免下次打开找不到文件。
- 键盘用户可通过标签焦点上的菜单键或 Shift+F10 打开同一菜单并完成重命名。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 对已打开的真实本地文件，用户 MUST 能从该标签的右键菜单启动重命名，无需关闭标签或离开应用。
- **FR-002**: 重命名输入 MUST 预填当前文件名（含扩展名），并允许取消；取消 MUST NOT 改变文件或标签。
- **FR-003**: 确认后系统 MUST 仅在原目录内更改该文件的名称，不得把改名变成移动到其他目录，也不得覆盖已存在的同名项。
- **FR-004**: 成功后该标签 MUST 保持打开，显示新名称，并继续关联同一份内容，包括未保存修改。
- **FR-005**: 成功后，依赖该路径的界面提示（窗口标题、状态栏、文件树、悬停提示）MUST 改为新路径，不得继续显示旧路径。
- **FR-006**: 失败时系统 MUST 向用户说明原因（至少区分「同名已存在」与其他失败），并保持改名前的文件、标签路径与未保存内容。
- **FR-007**: 空名称、与当前名相同的名称，以及含路径分隔符的名称，MUST 被拒绝且不改变任何文件。
- **FR-008**: 草稿、双文件对比、尾随台等没有单一磁盘文件的标签，其右键菜单 MUST NOT 提供重命名。
- **FR-009**: 重命名 MUST 对各类已打开的真实本地文件可用，不限于当前正处于文本编辑的文件。
- **FR-010**: 改名成功后，最近打开与收藏中的旧路径记录 MUST 更新为新路径；未涉及的记录保持不变。
- **FR-011**: 标签上的重命名与文件树中的重命名 MUST 遵守同一套名称规则与失败提示，避免同一操作在两处结果不同。
- **FR-012**: 键盘焦点在标签上时，MUST 能通过既有菜单键打开含重命名的同一菜单。

### Key Entities

- **打开的文件标签**: 用户正在查看的一个标签。真实本地文件标签有磁盘路径与显示名；草稿、对比、尾随台没有可单独改名的磁盘文件。
- **文件名**: 路径最后一段，含扩展名。本次只允许替换这一段，目录不变。
- **未保存修改**: 仍留在该标签中、尚未写回磁盘的内容。改名不得丢弃或转移到其他标签。
- **路径记录**: 最近打开与收藏里记住的旧路径。改名成功后应指向新路径。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 对已打开的本地文件，用户可在标签右键菜单内开始重命名，无需关闭文件或切换到系统文件管理器。
- **SC-002**: 在名称合法且目标未被占用时，用户确认后 2 秒内看到标签显示新名称，且原目录中该文件已使用新名称。
- **SC-003**: 带未保存修改的文件完成改名后，修改仍在同一标签中，标签不关闭、内容不回退到改名前的磁盘版本。
- **SC-004**: 同名冲突、非法名称、文件不存在、占用或权限不足时，100% 保持原文件与原标签路径，并向用户给出可理解的结果。
- **SC-005**: 草稿、对比、尾随台标签的右键菜单中不出现重命名；真实本地文件标签的右键菜单中出现重命名。
- **SC-006**: 首次使用该入口的用户，在不查阅说明的情况下，能独立完成一次成功改名或一次明确的取消。

## Assumptions

- 「标签」指应用内已打开文件的标签，不是操作系统桌面上的文件图标。用户提到「去桌面改」是指离开应用、到系统文件管理器改名。
- 重命名沿用文件树里已有的改名体验：菜单项、预填文件名的输入框、同名已存在与失败提示保持一致，而不是在标签上直接改字。
- 一次只重命名当前标签对应的那一个文件，不批量改名，也不通过标签重命名其所在文件夹。
- 新名称停留在原目录。跨目录移动仍不在本次范围内。
- 只读（标签锁或全局只读）不阻止重命名文件名；磁盘权限不足则改名失败并提示。
- 界面语言继续支持中文与英文，新增或复用的菜单与提示随界面语言切换。
- 不新增离开本机的网络访问，不改变文件正文的保存规则。
