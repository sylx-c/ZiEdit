# Contract: 标签重命名

## 菜单

真实本地文件标签的右键菜单，以及标签获得焦点后的菜单键 / Shift+F10，包含「重命名…」。该项与关闭、复制完整路径、在文件管理器中显示并存，不替换它们。

以下标签没有该项：

- `draft://`
- `compare://`
- `tail://`

标签锁和全局只读不隐藏、不禁用该项。

## 输入

选择后打开与文件树相同的名称输入。初始值为当前文件名，含扩展名。

| 输入 | 结果 |
|---|---|
| 取消、空、仅空白 | 不调用改名 |
| 与当前文件名完全相同 | 不调用改名 |
| 含 `/` 或 `\` | 不调用改名 |
| 其他名称 | 目标为原目录下的该名称 |

输入不提供目录选择。

## 磁盘操作

使用现有 `file_rename(from, to)`：

| 哨兵 | 用户可见结果 | 内存 |
|---|---|---|
| 成功 | 短暂提示已重命名 | 才允许迁移 |
| `EXISTS` | 同名项已存在 | 不变 |
| `NotFound` / 文件已不在 | 文件已不在，不新建文件 | 不变 |
| 其他 I/O 失败 | 重命名失败及原因 | 不变 |

设备路径继续被拒绝。操作不覆盖目标，不写出文件正文。

## 成功后的界面

- 该标签保持打开，显示新文件名。
- 未保存修改、脏标记、滚动、书签和只读锁仍属于这一标签。
- 窗口标题、状态栏路径、悬停提示和文件树改为新路径。
- 扩展名变化且用户未锁定路由时，展示跟随新扩展名；不另存一份。
- 最近打开与收藏中的旧路径改为新路径，顺序不变，不出现重复。
- 其他标签、子目录中已打开文件不变。

## 持久化操作

新增一个路径记录迁移，不新增 IPC 字段：

```text
paths_rename_records(from: string, to: string) -> Result<(), error>
```

在与最近/收藏相同的持久化锁内：

1. 规范化 `from` 与 `to`。
2. 读 `recent.json` 与 `favorites.json`。
3. 只替换完全相等的路径；新路径已存在则删除旧路径。
4. 原子写回有变化的文件。

配置写失败不表示磁盘改名失败。旧配置字段保持兼容，缺省组列表仍为空。
